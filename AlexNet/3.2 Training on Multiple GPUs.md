# 3.2 다중 GPU 훈련 (Training on Multiple GPUs)

> **논문**: A. Krizhevsky, I. Sutskever, G. E. Hinton, "ImageNet Classification with Deep Convolutional Neural Networks", *NeurIPS*, 2012. (AlexNet)

> 💡 **한 줄 요약**
> GPU 한 대의 메모리(3GB)에 다 들어가지 않는 큰 신경망을 **GPU 두 대에 반씩 나눠** 훈련합니다. 두 GPU는 **특정 층에서만** 서로 정보를 주고받습니다. 그 결과 오류율도 낮아지고 훈련 시간도 조금 줄었습니다.

---

## 1. ⚠️ 문제점: 단일 GPU의 한계

| 항목 | 내용 |
|---|---|
| 사용 GPU | NVIDIA **GTX 580** |
| 메모리 | **3GB** (당시 기준으로도 작음) |
| 결과 | GPU 한 대에 올릴 수 있는 **네트워크 크기가 제한**됩니다. |

> 📌 **핵심 포인트**
> 훈련 데이터 **120만 장**은 GPU 한 대에 들어가는 것보다 **더 큰 네트워크를 훈련하기에 충분한 양**입니다.
> 즉, 데이터는 넉넉한데 **GPU 메모리가 모델 크기의 발목을 잡는** 상황이었습니다.

---

## 2. 💡 해결책: 교차-GPU 병렬화 (Cross-GPU Parallelization)

네트워크를 **GPU 두 대에 나눠** 올려 메모리 한계를 극복합니다.

- 당시 GPU는 **서로의 메모리를 직접 읽고 쓸 수** 있었습니다.
- 호스트(CPU) 메모리를 거칠 필요가 없어서, 여러 GPU로 나눠 계산하기에 특히 잘 맞았습니다.

```
        ┌──────────── 기존 방식 ────────────┐
        │  GPU A  ⇄  CPU 메모리  ⇄  GPU B   │   ← 느림
        └───────────────────────────────────┘

        ┌──────────── 이 논문 ──────────────┐
        │  GPU A  ⇄⇄⇄⇄⇄⇄⇄⇄⇄⇄⇄⇄⇄⇄⇄  GPU B   │   ← 직접 통신, 빠름
        └───────────────────────────────────┘
```

---

## 3. 🔀 훈련 방식과 GPU 간 통신

### ① 커널을 반씩 나누기

각 층의 커널(뉴런)을 **절반은 GPU 1에, 나머지 절반은 GPU 2에** 배치합니다.

### ② 특정 층에서만 통신하기 (추가 "트릭")

GPU끼리 매 층마다 정보를 주고받으면 느려집니다. 그래서 **정해진 층에서만** 통신합니다.

| 층 | 입력을 받는 범위 | GPU 간 통신 |
|---|---|:---:|
| **3번째 층** | 2번째 층의 **모든** 커널 맵 (두 GPU 모두) | ✅ 있음 |
| **4번째 층** | 3번째 층 중 **같은 GPU에 있는** 커널 맵만 | ❌ 없음 |

```
            GPU 1                    GPU 2
  Layer 2  [■■■■■■]               [■■■■■■]
              │  ╲               ╱  │
              │    ╲ ✅ 교차 ✅ ╱    │
              │    ╱         ╲      │
  Layer 3  [■■■■■■]               [■■■■■■]
              │                     │
              │   ❌ 교차 없음 ❌   │
              │                     │
  Layer 4  [■■■■■■]               [■■■■■■]
```

### ③ 연결 패턴은 어떻게 정했나?

- 어느 층에서 통신할지는 정답이 정해져 있지 않습니다. 그래서 **교차 검증**(cross-validation)으로 실험하며 골랐습니다.
- 목표는 **통신량을 전체 연산량에 비해 감당할 만한 수준**으로 정밀하게 맞추는 것입니다.

> 🍳 **쉬운 비유**: 주방 두 곳에서 요리사들이 나눠 요리하는 상황
> - 모든 단계마다 서로 재료를 주고받으면 → 복도가 막혀 오히려 느려집니다.
> - **중요한 단계에서만** 재료를 주고받으면 → 협업 효과는 살리고 이동 시간은 줄입니다.

---

## 4. 🏆 결과와 효과

### 기존 연구와의 비교

Cireșan 등이 쓴 **"컬럼형(columnar)" CNN**과 비슷한 구조입니다.

| 구분 | 컬럼형 CNN (Cireșan 등) | AlexNet 2-GPU 구조 |
|---|---|---|
| 컬럼(=GPU) 관계 | **서로 독립적** | 일부 층에서 **서로 연결** |

### 📊 성능 향상

비교 대상은 **GPU 한 대에서 훈련한 네트워크**입니다. 이 네트워크는 각 합성곱 층의 커널 수가 절반입니다.

| 지표 | 오류율 감소 |
|---|:---:|
| **Top-1 오류율** | ⬇️ **1.7%p** |
| **Top-5 오류율** | ⬇️ **1.2%p** |
| **훈련 시간** | ⬇️ 2-GPU 쪽이 **약간 더 짧음** |

> 📝 **참고**: 단일 GPU 네트워크도 마지막 합성곱 층과 완전 연결 층의 크기는 같습니다. 그래서 두 네트워크의 매개변수 수 차이는 생각보다 크지 않습니다. 매개변수 대부분이 완전 연결 층에 있기 때문입니다. 2-GPU 쪽이 오히려 불리한 조건에서 비교한 셈입니다.

---

## 5. 📝 핵심 결론

$$
\text{모델을 GPU 2대에 분할} \;+\; \text{선택적 통신} \;\Rightarrow\; \text{더 큰 모델} \cdot \text{더 낮은 오류율} \cdot \text{더 빠른 훈련}
$$

하드웨어 한계 때문에 고안한 방법이지만, **모델을 여러 장치에 나눠 훈련하는 모델 병렬화**(Model Parallelism)의 초기 사례가 되었습니다.
